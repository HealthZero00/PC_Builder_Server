# Вольтаж

Серверная часть мобильного приложения для автоматизированного подбора, сравнения цен и проверки совместимости комплектующих ПК.

Система агрегирует каталоги трёх российских ритейлеров — **DNS**, **«Ситилинк»** и **«Регард»** — в единую базу данных, устраняет дублирование товарных позиций между магазинами и предоставляет REST API для мобильного Android-клиента, который проверяет техническую совместимость собранной пользователем конфигурации (сокет, чипсет, память, блок питания, габариты).

Выпускная квалификационная работа, направление 09.03.02 «Информационные системы и технологии».

## Возможности

- Автоматический сбор цен и характеристик с DNS, «Ситилинк» и «Регард» в фоновом режиме (`parser_dns.py`, `parser_engine.py`, `parser_regard.py`)
- Дедупликация товаров между магазинами — алгоритм трёхуровневого сопоставления названий, артикулов и нечёткого сравнения текста (`matcher.py`)
- Многоуровневая проверка совместимости конфигурации: сокет/чипсет, тип и объём памяти, мощность блока питания с запасом, геометрические ограничения (`build_validator.py`)
- Хранение каталога в PostgreSQL с кэшированием в оперативной памяти для субсекундного времени отклика (`database.py`)
- Асинхронный REST API на FastAPI

## Структура проекта

```
.
├── main.py                  # точка входа FastAPI, маршруты REST API, фоновые задачи парсинга
├── database.py               # подключение к PostgreSQL, загрузка/сохранение каталога
├── matcher.py                 # сопоставление и дедупликация товаров между магазинами
├── build_validator.py         # проверка технической совместимости сборки
├── parser_engine.py            # парсер «Ситилинк» (Camoufox/Playwright)
├── parser_dns.py               # парсер DNS (Camoufox/Playwright)
├── parser_regard.py            # парсер «Регард» (Camoufox/Playwright)
├── requirements.txt
└── .env                        # переменные окружения (не публикуется, см. .gitignore)
```

## REST API

| Метод | Эндпоинт | Описание |
|---|---|---|
| GET | `/components` | возвращает каталог товаров по категории с пагинацией и поиском |
| GET | `/compatibility-check` | проверяет совместимость переданного набора компонентов |
| GET | `/health` | состояние сервера: количество товаров в кэше, статус парсера |

## Запуск проекта

1. Установить зависимости:
   ```bash
   pip install -r requirements.txt
   ```

2. Создать файл `.env` в корне проекта по образцу:
   ```env
   ENABLE_PARSER=true

   # Локальная база данных
   DB_LOCAL_HOST=localhost
   DB_LOCAL_NAME=pc_configurator
   DB_LOCAL_USER=postgres
   DB_LOCAL_PASS=your_password_here

   # Удалённая база данных (продуктивный сервер)
   DB_REMOTE_HOST=your_vps_ip
   DB_REMOTE_NAME=pc_configurator
   DB_REMOTE_USER=postgres
   DB_REMOTE_PASS=your_password_here
   ```
   Файл `.env` добавлен в `.gitignore` и не должен попадать в репозиторий.

3. Запустить сервер:
   ```bash
   python main.py
   ```
   Сервер поднимется на `http://0.0.0.0:8000`. При первом запуске каталог загружается из PostgreSQL в кэш; если `ENABLE_PARSER=true`, в фоне запускается последовательный цикл сбора данных «Ситилинк → Регард → DNS».

## Мобильный клиент

Android-приложение (Kotlin, Jetpack Compose) взаимодействует с сервером через Retrofit 2 по HTTPS и хранит сборки локально в Room для работы без интернета. Репозиторий клиента — отдельный проект.
